# Publish run provenance as STAC item properties (#17)

Every published item now carries eleven `nge:` provenance properties, mirrored as `NGE_` GDAL
tags on the COGs. All of them are `null` on production data today, and that is the correct
reading — `NewGraphEnvironment/floodplains#33` is **forward-only**, so an area modelled before it
lands carries no provenance until it is re-run. Publishing the null rather than omitting the key
is the point: an absent property reads as "not implemented", a null one as "we looked and there
was not one", and only the second is true.

The work was started while the producer was still in flight. Rather than guessing a schema or
posting a contract at an issue a live session had already read, the producer's declared decisions
were read from its own working tree — which had already written this repo's requirement ("stac#17
treats the block as optional") and had already decided the file shape.

## Measurement

Three encodings silently destroy a null, and two of them were live in the original design:

| layer | default behaviour | fix |
|---|---|---|
| `jsonlite` | `NA_real_` serialises as the **string** `"NA"` | `na = "null"` |
| `jsonlite` | an R `NULL` serialises as `{}`, which passes Python's `is not None` | `null = "null"` |
| GDAL | a colon in a tag key is a namespace separator, so eleven `nge:`-prefixed fields collapse into **one** `NGE` tag | keys are `NGE_<FIELD>` |

Both jsonlite arguments are byte-inert on the seventeen pre-existing fields. GDAL's empty string
is the only honest encoding of a null — `str(None)` writes the literal `'None'` — and it also
*deletes* an existing key, which is what makes it the clearing mechanism given `update_tags()`
merges rather than replaces.

`pystac` preserves null properties through `to_dict()`, a JSON round trip, `from_dict()` and
`validate()`. That was checked before anything was built on it.

## What review changed, and why it is the interesting part

Three rounds found nine issues. Two are worth recording as a pattern rather than as fixes.

**The same defect appeared at three levels.** A guard that reads only "expected key missing"
cannot distinguish a rename from a legitimate absence. Round 1 found it at the leaf
(`link_log`), round 2 found the identical shape one level up (`inputs`), round 3 named the
mechanism: a rename emits *two* signals, and the reader was reading one. That framing is what
ended it — the class is closed wherever a parent section's presence is itself evidence, and had
to be closed separately at the two depths where there is no parent (the document root, and the
scenario map keys, which are data and so needed a shape assertion instead).

**A guard added in one round was vacuous in the state the repo is actually in.** `check_cog_tags`
excluded `NGE_PROVENANCE_NULL` — which, until #33 lands, is the *only* `NGE_` tag on a COG. It
compared `{}` against `{}` for every item, and the tag could be overwritten with garbage
undetected.

One route published a **wrong value** rather than a null: `length(cur) != 1L` is a proxy for
"scalar" that a single-key object satisfies, so a leaf becoming `{"algorithm": "sha256"}`
published `"sha256"` as `nge:landcover_key` and counted as traced.

## Evidence

`review-round1.md`, `review-round2.md`, `review-round3.md` — the full findings, including the
items checked and found clean so a later round did not re-derive them.

Every guard was restored against a defect that must trip it and a control that must not. One
probe initially reported all four cases as stopping for an unrelated reason (an incomplete
fixture), which is why the controls are recorded alongside the failures.

## Deliberately not established

- **pgstac null survival.** Measured through `jsonlite` → `pystac` → `validate()`, **not**
  through `pypgstac load` and back out of the API, which needs a write to the live catalog. If
  pgstac strips nulls on dehydrate/hydrate, "publish the null" is unachievable through the API
  and the issue needs a sentinel-value decision. Close this before anyone relies on reading these
  properties from `images.a11s.one`.
- **The adapter against real upstream bytes.** The fixture was generated by sourcing the
  producer's own `fp_prov_set()`/`fp_prov_write()`, so the nesting, key sorting and null encoding
  come from their code — materially better than hand-written JSON, and still not interop
  validation, because we supplied the section contents. The `schema_version` pin and the
  rename hard-stops are the guards that cover a leaf rename; the mapping itself is unverified
  until #33 emits a real file.
- **The traceability floor.** Once #33 lands and areas are re-modelled, the release should refuse
  to publish when the reader finds nothing, rather than shipping all-null.
